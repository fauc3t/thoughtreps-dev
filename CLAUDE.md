# Thought Reps

Local-first iPhone and iPad app: write a Markdown thought, and it resurfaces on the timeline after an interval (7 days by default). Specs, plans and mockups live in `designs/` (new specs go there too); `landing/` is static landing-page prototypes (not shipped; `site-landing/` is the real landing site, a port of `landing/7-ink.html`, plus the prerendered help center at /help, the blog at /blog, and the privacy policy at /privacy and the support page at /support). `infra/` is the CDK app (landing hosting, DNS, email at hello@thoughtreps.com), `infra/mail-web/` the inbox UI, and `transfer-web/` the one-time export download page; see `infra/CLAUDE.md`. `content-pipeline/` holds unpublished blog and free-tool (printables) ideas and drafts (workflow in its `README.md`). `app-store-assets/` holds App Store product page and search creative, one folder per slot (regeneration steps in each slot's `README.md`). What's deployed in AWS is recorded in `INTEGRATIONS.md`. The sync server lives in the separate `~/dev/thoughtreps-aws` repo. Setup and commands are in README.md and DEVELOPMENT.md.

## Stack

Swift, SwiftUI, SwiftData, iOS 18+, Swift Testing. Two third-party dependencies, both pinned exact: MarkdownUI (chosen over Textual as the stable option, though it's in maintenance mode) and ZIPFoundation (the backup zip). Add packages via `project.yml` `packages:`; the SwiftPM lockfile `ThoughtReps.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` is tracked, so commit it when versions change. Paid Apple Developer account. The web side is TypeScript in a pnpm workspace (`infra`, `infra/mail-web`, `site-landing`, `transfer-web`; Node 24+); tests are `pnpm test`, `pnpm typecheck`, `pnpm lint` at the root.

## Workflow

- Web/infra deploys are manual `cdk deploy` with `--profile thoughtreps-prod-legacy` (no CI), into an AWS account shared with strands prod. Read `infra/CLAUDE.md` first, and update `INTEGRATIONS.md` when a deploy changes a stack's status, outputs or ids (content-only deploys need no entry).

- `project.yml` is the source of truth. `ThoughtReps.xcodeproj` is generated and gitignored: edit `project.yml`, run `xcodegen`, never hand-edit the project. Re-run after adding or removing files.
- Signing lives in `Config/Local.xcconfig` (gitignored, copy from the `.example`).
- Test: `xcodegen && xcodebuild test -scheme ThoughtReps -destination 'platform=iOS Simulator,name=<simulator>'`, with a name from `xcrun simctl list devices available`.

## Rules

- **Scheduling is pure.** All resurfacing logic lives in `ThoughtReps/Scheduler/` as pure functions that take `now` as a parameter; never call `Date.now` inside them. `ThoughtStore` methods also take `now` with no default; views pass `.now`. Cover changes with tests in `ThoughtRepsTests/`.
- **Reminders: plan purely, schedule in one place.** What to notify and when is `ReminderPlanner` (pure, in `Scheduler/`). Only `NotificationScheduler.reschedule` touches `UNUserNotificationCenter`; it is serialized and removes stale reminders before adding the planned ones, so no more than 10 are ever pending (7 daily plus follow-ups at +14, +30 and +90 days, then silence). Counts come from `fetchCount` with `ReminderPlanner.countedPredicate`, never by loading thoughts; `plan` takes the count as a closure and stays pure. Local notifications only (no push), no app icon badge, and pinned thoughts never count.
- **Tag links go through `TagLinker`.** It rewrites `#tag` to a `thoughtreps-tag:` link before MarkdownUI renders, using `TagParser`'s rules; don't parse tags separately in the renderer.
- **`ThoughtStore` owns all writes.** Views read via `@Query` but mutate (create, edit, schedule, tags, delete) only through the store.
- **Assume hundreds of thousands of thoughts.** Counts and existence checks are `fetchCount`/`fetchLimit` queries with a `#Predicate`, never `@Query` arrays or relationships filtered in memory (SwiftData can't count through `tags?.isEmpty`; see `ThoughtCounts.untagged`). Load `Thought` objects only to display them, and use `propertiesToFetch` when a few fields are enough. No query per thought (a query per tag is fine; tags are few). Keep predicates in reusable builders (`ThoughtCounts`, including the Timeline's `timeline`/`upcoming`/`nextUp` in `Stores/TimelineQueries.swift`, and `ReminderPlanner.countedPredicate`, `ThoughtCounts.activeWithoutCopies`, the paged `conflictCopies(limit:in:)`, and the link builders `ThoughtCounts.targets(of:in:)` (one batched fetch per displayed thought) and `ThoughtCounts.linkedFrom(_:in:)` (capped at 50 + `fetchCount`, archived owners excluded)) and test them against an in-memory container. Anything in `body` that scales with thought count belongs in a query or a value refreshed on save. Known exceptions: the Timeline's "show all" mode and the Archive list (they display every thought; the default Timeline queries only pinned, due and recently viewed thoughts) and the DEBUG-only `IntegrityChecker`.
- **Models stay CloudKit-compatible** so iCloud sync can be switched on later without a migration: every stored property has a default, relationships are optional with inverses declared on one side, no `@Attribute(.unique)` (e.g. tag uniqueness is enforced in `ThoughtStore`), and enums are stored as raw strings.
- **Schema changes need a migration, after launch.** The app container is built from `SchemaV1` + `ThoughtRepsMigrationPlan` (`Models/SchemaVersions.swift`). Until the first external TestFlight or App Store release, edit `SchemaV1` in place and regenerate `ThoughtRepsTests/Fixtures/default.store` with `FixtureGenerator` (steps in the README beside it); internal TestFlight builds are still pre-launch, so after an in-place model change testers delete and reinstall the app (otherwise the store fails to open and the app shows "Couldn't open your thoughts"). From the first external release on, `SchemaV1` is frozen: before ANY model change, snapshot V1 into nested copies, then add `SchemaV2` and a migration stage. Never regenerate or edit a shipped fixture; add a new one. `PersistenceTests.openV1FixtureWithMigrationPlan` guards this.
- **Writers set the change clock for every field group they change,** stamping through the store's skew-safe `stamp` (`max(now, highestSeen + 1 ms)` when sync is on). Content (body, blocks, images, tags) is `updatedAt`; schedule (`nextDueAt`, interval, mode, `learnIntervalDays`) is `scheduleChangedAt`; pin/archive and `conflictOfID` (a plain id like `linkedThoughtID`, never the thought's own; import and sync conflict copies set it) are `stateChangedAt`. `markViewed` bumps the schedule clock only when it actually moves `nextDueAt`. `viewCount`/`lastViewedAt` have no clock (import takes the max). `Tag.updatedAt` is set only by an explicit color choice, so implicit tags stay `.distantPast`. A writer that skips its clock lets a backup import silently undo its change. `ThoughtStore.delete` writes a `Tombstone` in the same save (prep for sync: `SyncReconciler` queues unsynced ones; `deleteAll` clears them, and they aren't exported). Extend `IntegrityChecker` with any new clock or tombstone invariant.
- **Saves can fail and must not be swallowed.** `ThoughtStore.persist()` logs, rolls back, and reports to `SaveErrorCenter` (shown as an alert). Store writers return `Bool` (`@discardableResult`); a failed create returns a detached thought (`modelContext == nil`). The editor closes only on success so drafts survive. Rolling back certain write shapes crashes SwiftData, so new writes on a stored thought must follow the rules in the `persist()` note (`update` saves in steps and may be partly saved on failure; `delete` removes children explicitly). Images follow this: new inline images are saved in their own step before the body edit, and inline images whose `![](img:<uuid>)` token left the body are deleted explicitly. `PendingImageSaves` marks a thought across that step; if the edit and the take-back both fail (or the app dies), the mark stays and `cleanUpPendingImageSaves()` (run at launch from `RootTabView`, and by `update` first) deletes the thought's tokenless inline images.
- **The sync outbox is derived state; keep it fed.** `sync.sqlite` (`Sync/`, `SyncState` actor) sits in Application Support/Sync, excluded from backup, never the source of truth, with no SwiftData schema change. Sync is on only after `configure(vaultID:)` (DEBUG-only for now: via `THOUGHTREPS_SYNC_VAULT`, or at launch from a vault key in the Keychain, env vars winning); off, enqueue is a no-op. Every `ThoughtStore` writer that changes a synced field or clock enqueues what it changed via `syncState.enqueue`, alongside the reindex; `SyncReconciler` repairs drift at launch. The engine must push every outbox entry and skip no-ops by base hash, not by clock fingerprint (some content changes don't move `updatedAt`). Extend the randomized tests' outbox drain check when adding a writer. The wire format is frozen: sync has its own `SyncWireV1` structs (never the backup's types), pinned by `SyncGoldenTests`, and an unknown `TR*` magic or key generation parks as update-required, never an error. Editor saves go through `ThoughtStore.saveEdit`, which 3-way merges the draft when the stored thought changed meanwhile (overlap: draft wins, the stored version becomes a conflict copy). Remote changes apply only via `ThoughtStore.applyRemote` (shares import's merge) and must not enqueue echoes; its clean content merges (`ContentMerge`) and conflict copies are new local writes, so they are stamped and enqueued. No base with differing content makes a copy, never a guess. `attempts` keeps a first push's plaintext as the merge base until a real base lands. `HTTPSyncTransport` has its own frozen `SyncHTTPWireV1` structs, pinned by golden fixtures in `ThoughtRepsTests/Fixtures/SyncWireV1/` mirrored byte for byte from `thoughtreps-aws` (`infra/lambda/sync/fixtures/wire-v1/`), so changing one means changing both; a server refusal (400/401/403/404/410) stops the engine (`Attention.serverRefused`). `HTTPSyncTransport` takes a `SyncAuth`: `.devSecret` (the dev `Authorization` plus `x-tr-vault`; simulators and `scripts/sync-integ.sh`) or `.session` (bearer only, from `SyncSessionProvider`, which keeps the token in memory, never persisted or logged, refreshes it near expiry, and on a 401 refreshes and retries once; a second 401 is `serverRefused`). The Sync lab's sign-in (`SyncAccountService`) uses sync's own App Attest key (Keychain service `com.thoughtreps.sync.appattest`, separate from the export-link and feedback key) and Sign in with Apple, then creates the vault; the vault key (K, vault id, user id) is one non-synchronizable `AfterFirstUnlockThisDeviceOnly` Keychain item. With the "Save sync key to iCloud Keychain" toggle on (UserDefaults, default on) the key is also saved as a separate synchronizable item (service `com.thoughtreps.sync.credentials.icloud`); the local item stays authoritative. "Sign out and forget key" deletes only the local item and the App Attest key id, and leaves the account, vault and iCloud copy. A new device joins through App Attest-signed `POST /pair` from the iCloud copy, a recovery code (`K_auth` proof) or a QR invite (`thoughtreps-pair:v1:...`, scanned with VisionKit, no URL scheme). `JoinGate` (pure) confirms first, then offers merge or erase for existing thoughts; the erase runs only after `/pair` succeeds and the key is saved, so a failed pair erases nothing. The recovery code and `nameSealed` (`TRSN`) formats are permanent, pinned by golden tests. A stale App Attest key is re-registered once automatically (a new server device). While sync is on every stamp is observed into `highestSeen` and offset by the server clock (`ServerClockOffset`); scheduler and due dates keep the real `now`. Blobs (images, files, records over 64 KiB) go through `putBlob`/`getBlob` (images and files skip any `hasBlob` pre-check: `upload-urls` skips present blobs and refreshes old ones; `hasBlob` stays in the protocol but the engine doesn't call it), which take the epoch and talk to presigned S3 URLs from `blobs/upload-urls` and `blobs/download-urls`; those S3 requests carry only the signed headers, never the dev `Authorization` or `x-tr-vault`, and an expired URL (403) is refreshed once. A push refused with 409 `blob_missing` re-uploads the record blobs and retries once, then ends the cycle with an error (not a stop). A transport without blobs (`supportsBlobs` false) holds those thoughts as `waitingForBlobs`, meta included, until it has them. Blob names are server-checked as 43 URL-safe characters. A 413 `quota_exceeded` holds only that thought (retried each cycle, engine keeps going). Leaving sync ("Erase this device and leave sync") deletes this device on the server first and clears nothing if that fails (a 401/403 means the device was already removed: use "Sign out and forget key"); only then `SyncEngine.stop()` (cancels and awaits the in-flight cycle, so nothing applies, commits or pushes after it), then the local key, App Attest key id and sync state go, the iCloud copy stays, and `ThoughtStore.deleteAll` (erase) runs last. Erase is always local: the app has no "Erase on all devices" (the server route stays unused; the engine's epoch-changed stop is a safety net, never an automatic erase). "Delete sync data" calls `DELETE /account`, signs in with Apple and retries once only on 403 `reauthentication_required`, aborts if the signed-in vault isn't this device's, then clears like a leave and deletes the iCloud copy too; every device keeps its thoughts. A Keychain key with no sync history (no state file, another vault's state, or empty state) doesn't auto-start (`SyncDebugSession.launch`); the Sync lab asks "Resume syncing with this vault?" (env vars still win). Blob garbage collection (`SyncEngine.collectGarbageIfDue`) asks the server for a run only from a device with complete state (outbox empty except storage-limit holds, nothing parked or held, same epoch, head == cursor), because an incomplete live list makes the server delete in-use blobs; its failures never stop the engine.
- **Test vaults get cleaned up.** The device harness records every `test-` vault in a ledger and erases it through the dev-only `POST /dev/vaults/{id}/erase` (exit trap, next-run sweep, final check that fails the run). Before each uninstall it runs the DEBUG-only "Reset sync test state" (Sync lab, or launch arg `-TRResetSyncTestState <nonce>`; `SyncTestReset`), which deletes the local vault key, sync App Attest key id and `sync.sqlite`, and the iCloud Keychain copy only for `test-` vaults. UI tests launch with `syncSaveKeyToICloudKeychain` off.
- **Keep the integrity checker and randomized tests current.** `IntegrityChecker` (`Stores/`) is a pure, read-only invariant check that runs at launch in DEBUG and only logs. When adding or changing a model field, store write, or invariant, extend it and the seeded random-operation tests (with injected save failures) so every operation keeps the store violation-free. It covers images too: data and thumbnails present, every inline image has a token and every token resolves, gallery images match their block's thought with contiguous order, images sit only in galleries or inline, no duplicate ids.
- **The search index is derived; keep it in sync.** SQLite FTS5 in `Search/`, next to the store and excluded from backup, never the source of truth. Any `ThoughtStore` writer that changes body, block content or titles, tag names, or archive state must submit a reindex; index errors are logged, never shown as save errors. `SearchReconciler` repairs drift at launch (off the main thread, via an `updatedAt` + archive-flag fingerprint) and rebuilds a missing or damaged file. `SearchModel` takes an optional `isIncluded` filter (the link picker's exclusions) and keeps paging until a page's worth is visible. Known gaps: after a mid-session index failure search is incomplete until next launch, and a write that leaves `updatedAt` unchanged can leave stale text until the next edit. Extend `SearchIndexChecker` and the randomized tests when changing any of this.
- **The share extension never touches SwiftData.** `ThoughtRepsShare` only writes `InboxItem` files (plus, for a shared non-text file, one copied attachment) into the App Group inbox via `Shared/`; the app imports them through `InboxImporter` -> `ThoughtStore.create`. The store stays in the app container: moving it to the App Group would need a migration plan, so don't do it casually. Keep the extension free of MarkdownUI and SwiftData (extension memory limit).
- **The app's only network calls are to our API** (`transfer.thoughtreps.com/api/v1`) **and presigned S3**. The one exception is DEBUG-only sync to a dev or local server named by launch vars (`SyncDebugSession`), or, from the Sync lab's sign-in, to the dev API constant (`THOUGHTREPS_SYNC_URL` overrides; it also calls Apple's Sign in with Apple); it ships nowhere yet (DEBUG-only too: Settings > Developer > Sync lab, and a `THOUGHTREPS_SYNC_STATUS_FILE` status snapshot that `scripts/sync-integ.sh` reads, with counts and a content digest; neither holds the key, a session token or thought text), and the privacy manifests and policy change when sync ships. The real-device harness (`scripts/sync-device-integ.sh`) adds no app network calls: only its UI test runners talk to the Mac's coordinator (`scripts/sync-coordinator.py`), and it reads the snapshot through the DEBUG-only `syncStatusProbe` accessibility element (`THOUGHTREPS_SYNC_STATUS_PROBE`; a relative status file path resolves inside the app container). Feedback and creating or revoking an export link go through `AppAttestClient`; the public, unsigned export-link `status`/`claim`/`done` calls (`ExportLinkImportService`, for importing a link) and the presigned S3 `PUT` (upload) and `GET` (download) of the encrypted export need no App Attest. Feedback never includes thought content; an export link upload does carry it, but only as a file encrypted on device (AES-GCM) whose key never leaves the device except in the link's URL fragment, and importing decrypts on device with that fragment. The share extension stays network-free. App Attest is unavailable in the simulator, so sending feedback or creating an export link needs a real device; Universal Links (`applinks:transfer.thoughtreps.com`) can't be tested there either.
- **Privacy manifests and the privacy policy change together.** Changing network calls, data the app sends or stores off-device, server-side records, or adding a required-reason API means updating both `PrivacyInfo.xcprivacy` files (`ThoughtReps/Resources/`, `ThoughtRepsShare/`) and the privacy policy (`site-landing/src/content/privacy.ts`) in the same change. Release checks (App Store privacy answers, export compliance) are in DEVELOPMENT.md, "Releasing to the App Store".
- **Generated plists and entitlements come from `project.yml`** (`info:`/`entitlements:`, gitignored output); never hand-edit them.
- **Themes go through the Ink tokens.** Colors, fonts and card shapes come from `InkStyle.swift`, which reads `ThemeManager` (`AppTheme.swift`); don't hard-code them in views. The Ink theme must stay identical to the asset catalog (`InkStyleTests`). Always-dark themes pin the windows' `overrideUserInterfaceStyle`, since `preferredColorScheme(nil)` can't reliably undo a forced scheme. Settings and the editor keep the standard iOS look. The choice is in UserDefaults (no schema change). Premium themes are only an idea (TODO.md).
- **The rating prompt state lives in UserDefaults, not SwiftData** (`RatingPrompt`; no schema change). A due open is decided by the pure `Scheduler.countsAsDueOpen` inside `markViewed`, and a Learn rating (`review`) counts as a due open too; at 10 the prompt is asked once ever, from the main timeline. Tests that call `markViewed` or `review` must inject a throwaway suite (`RatingPrompt.throwaway()`), never the standard defaults.
- **The reminder prompt is UserDefaults too** (`ReminderPrompt`, key `reminderPromptAsked`; no schema change). Offered once ever, after the editor closes on the first thought created there. Tests use throwaway suites.
- **Layout follows `horizontalSizeClass`.** Regular width is the three-column `SplitRootView`, compact is the iPhone tab view. `ThoughtSelection` (environment object) exists only in the split layout; list rows are `ThoughtLink` (a selection button there, a `NavigationLink` otherwise), and anything that leaves a thought (snooze, archive, delete) goes through `leave()`. The editor's keyboard format bar follows its text view's size class, not the device idiom or the keyboard window's traits. Never auto-select a thought: opening one is a view and requeues it. The one exception is a fold or unfold, which carries the selected tab's already-open thought and pushed screens across (`LayoutCarry`, `RootTabView.carryAcrossLayouts`) with a `ViewHandoff` that counts every carried thought entry (selection and linked-thought pushes, which stay pushes on the detail column's `ThoughtSelection.detailPath`, without changing the selection; `clear(ifSelected:)` truncates it), so no remounted detail, covered ones popped to later included, records a second view; it doesn't expire and is cleared by the next `select`/`clear` or carry. Editor sheets are presented from the root, so they survive a window resize.
- **One scene only.** Multiple windows are disabled (`UIApplicationSupportsMultipleScenes` off) because `AppNavigation`, `EditorShortcuts` and `BackupModel` are singletons; per-scene state comes first. Keyboard shortcuts (`AppCommands`, the editor's ⌘↩/Esc) are guarded by `ModalPresence` so they pause under a sheet or dialog. Dropped images go through `ImageIntake`, the same processing as the picker; other dropped files become File blocks via `FileIntake`; non-file links are ignored, never fetched.
- **New-thought requests go through `AppNavigation.requestNewThought`.** The request is held as `pendingNewThought` until `RootTabView` consumes it (so it works on cold launch) and is dropped while a sheet is up; App Intents (`NewThoughtIntent`, Action button/Siri/Shortcuts) only call it, open the editor empty (no tag prefill) and never touch SwiftData.
- **Conflict copies (`conflictOfID` set) are resolved, not browsed.** They stay out of the default timeline, `upcoming`, the main show-all and `ReminderPlanner.countedPredicate`; the "Needs a look" row opens `ConflictResolveSheet` (`AppNavigation.requestResolve`), never `ThoughtDetailView`, so a copy is never requeued. This ships in release builds, unlike the rest of sync.
- **If the store can't open, show the error screen** ("Couldn't open your thoughts"); never fall back to creating an empty store.
- **Every documentation pass checks the help center.** `site-landing/src/content/help.ts` is user-facing product documentation, prerendered at thoughtreps.com/help, and must match what the shipped app does. A change that adds, removes or alters a user-facing feature, UI label, limit, setting or workflow updates the matching article; a brand-new feature gets a new article. Write only what's in the shipped app (not unshipped Study mode). Keep `related` slugs pointing at existing articles, and link new articles to and from related ones. Keep the casual, plain voice (a Flesch-Kincaid test caps each article), and refer to icons with `{icon:name}` tokens rather than naming them. When a UI label or screen changes, update or add the matching `example` mockup in `HelpExamples.tsx` (real labels and states from the Swift app). New icon glyphs come only from Lucide, and `site-landing/public/third-party-licenses.txt` (and `transfer-web/public/`'s) stays current. Tests enforce title (<=70) and description (<=160) lengths; the sitemap, robots.txt, per-page SEO and JSON-LD, and the Open Graph tags and link-preview cards (`og/*.png`, rendered by `src/og-image.tsx` at prerender) generate from `help.ts`, so don't hand-edit them. Each article's "Updated" date is its newest line in `git blame` at prerender (`content/helpDates.ts`), so deploy from committed changes.
- **The blog (`site-landing/src/content/blog.ts`, /blog) is SEO content for people new to the app.** Essays first: mention the app lightly, and only for what it ships. Same section format, inline syntax and generated SEO as help (`BlogPosting` JSON-LD). Check historical or factual claims before publishing. Tests cap reading level at grade 7.

## Product decisions

- **Opening a thought requeues it, unless it's in Learn mode.** `ThoughtDetailView` calls `ThoughtStore.markViewed` on appear for fixed-interval thoughts. The default Timeline freezes its row order per snapshot (`TimelineOrder`), so an opened row stays put until the next refresh instead of jumping to the bottom. Pinned thoughts aren't frozen but ordered by pin time (`stateChangedAt`, oldest first; `TimelineOrder.pinnedSorted`), so opening one never moves it. Learn mode (`IntervalMode.learn`, per thought, off by default) is the shipped part of Study mode: opening doesn't requeue, and a due Learn thought moves only via **Again** / **Got it** (`ThoughtStore.review`; `setLearnMode` toggles). The growth math is pure, in `Scheduler.afterReview`: the first Got it waits 3 days (`Scheduler.learnFirstGapDays`; the thought's interval isn't used in Learn mode, and the editor shows "Back" with the due day in its place), then each Got it multiplies the last wait (`Thought.learnIntervalDays`) by 1.7, at least +1 day, capped at 365; Again is tomorrow and resets the wait. Learn state is in the backup (`learnIntervalDays`). A visit from a link card (`ThoughtStore.recordVisit`) bumps only `viewCount`/`lastViewedAt`: no requeue, no schedule clock, no rating-prompt count. Don't change requeue-on-open for fixed thoughts without asking; the rest of Study mode (a deck, spec) is unbuilt.
- **v1 blocks are markdown (optionally blurred), image galleries, thought links and files** (`BlockKind.markdown` with `Block.isBlurred`, `BlockKind.gallery`, `BlockKind.thoughtLink`, `BlockKind.file`). A link block holds only `Block.linkedThoughtID`, a plain id with no relationship: it may dangle after the target is deleted, a thought has at most one link per target and never links to itself, it adds no search text, and adding or removing one is a content change (`updatedAt`; the target is untouched). Spec: `designs/Thought Reps — Linked Thoughts Spec.md`; built end to end: cards, walking, "Linked from", and the editor's "Linked thought" entry with its picker (full-text search; empty search lists the 20 most recently edited; excludes this thought, linked and archived ones). A file block holds one `FileAsset` (any type, capped at 5 MB by `FileAttachment.maxBytes`, which the share extension shares; images aren't capped, they go through `ImageProcessor`) and opens in Quick Look, whose share button covers Save to Files and Open in. Its filename is indexed in the search `titles` column; contents never are. The thought `body` is the first markdown block and stays on `Thought`. Old stored or exported kind "blurred" means blurred markdown (`migrateLegacyBlurredBlocks` at launch; import maps it).
- **Images and attached files live in SwiftData, not as files on disk** (differs from the spec). `ImageAsset` and `FileAsset` data and thumbnails are `.externalStorage`, so large bytes sit in `.default_SUPPORT/_EXTERNAL_DATA` beside `default.store`; the backup export reads the bytes through SwiftData, but any file-level backup must include that folder. `ImageProcessor` downsizes to 2048 px HEIC (JPEG fallback) and strips metadata. The renderer resolves `img:` URLs only from the thought's own images, never the network.
- **The `.thoughtreps` backup format is permanent.** A zip (`ThoughtReps/Services/Backup/`) whose first entry is a stored `mimetype` (`application/vnd.thoughtreps.export+zip`), then `manifest.json` (`formatVersion`, SHA-256 per entry), `tags.jsonl`, `thoughts.jsonl`, `images/<uuid>`, `files/<uuid>`. Bump `formatVersion` on any record change; once shipped, old versions must stay importable. Exception: record changes made before any build has shipped don't bump it; the rule applies from the first external TestFlight or App Store release. Import validates contents, not extension, and goes only through `ThoughtStore.importThoughts`: merge by thought id, group by group: content by `updatedAt`, schedule by `scheduleChangedAt`, pinned/archived by `stateChangedAt`, view counters by max, tag colors by `Tag.updatedAt`; each clock follows the winning side. Tags are derived from the body. Importing from an export link downloads to a temp file and hands it to `BackupModel.beginImport`, so it takes the same path; opening a link (Universal Link, `applinks:transfer.thoughtreps.com`) only shows status and never claims, since claiming burns the one-time link. The export link uploads this same file, encrypted on device (`TRB1` + nonce + ciphertext + tag, AES-256-GCM); the key stays in the link's `#` fragment and, until expiry, in the Keychain so Settings can re-offer or revoke it. Known limit: ZIPFoundation rewrites the central directory per entry, so export time is quadratic in image count (~1 s at 4k images, ~100 s at 40k).
- **No legacy data import for now.** Export/import is only for the app's own format. Importing the original Thought Reps data is still an open question in the spec; don't build it until that's answered.
