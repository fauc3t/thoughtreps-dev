# Thought Reps

Local-first iPhone and iPad app: write a Markdown thought, and it resurfaces on the timeline after an interval (7 days by default). Specs, plans and mockups live in `designs/` (new specs go there too); `landing/` is static landing-page prototypes (not shipped; `site-landing/` is the real landing site, a port of `landing/7-ink.html`, plus the prerendered help center at /help, the blog at /blog, and the privacy policy at /privacy and the support page at /support). `infra/` is the CDK app (landing hosting, DNS, email at hello@thoughtreps.com), `infra/mail-web/` the inbox UI, and `transfer-web/` the one-time export download page; see `infra/CLAUDE.md`. `content-pipeline/` holds unpublished blog and free-tool (printables) ideas and drafts (workflow in its `README.md`). `app-store-assets/` holds App Store product page and search creative, one folder per slot (regeneration steps in each slot's `README.md`). What's deployed in AWS is recorded in `INTEGRATIONS.md`. Setup and commands are in README.md and DEVELOPMENT.md.

## Stack

Swift, SwiftUI, SwiftData, iOS 18+, Swift Testing. Two third-party dependencies, both pinned exact: MarkdownUI (chosen over Textual as the stable option, though it's in maintenance mode) and ZIPFoundation (the backup zip). Add packages via `project.yml` `packages:`; the SwiftPM lockfile `ThoughtReps.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` is tracked, so commit it when versions change. Paid Apple Developer account. The web side is TypeScript in a pnpm workspace (`infra`, `infra/mail-web`, `site-landing`, `transfer-web`; Node 24+); tests are `pnpm test`, `pnpm typecheck`, `pnpm lint` at the root.

## Workflow

- Web/infra deploys are manual `cdk deploy` with `--profile thoughtreps-dev` (no CI), into an AWS account shared with strands prod. Read `infra/CLAUDE.md` first, and update `INTEGRATIONS.md` when a deploy changes a stack's status, outputs or ids (content-only deploys need no entry).

- `project.yml` is the source of truth. `ThoughtReps.xcodeproj` is generated and gitignored: edit `project.yml`, run `xcodegen`, never hand-edit the project. Re-run after adding or removing files.
- Signing lives in `Config/Local.xcconfig` (gitignored, copy from the `.example`).
- Test: `xcodegen && xcodebuild test -scheme ThoughtReps -destination 'platform=iOS Simulator,name=<simulator>'`, with a name from `xcrun simctl list devices available`.

## Rules

- **Scheduling is pure.** All resurfacing logic lives in `ThoughtReps/Scheduler/` as pure functions that take `now` as a parameter; never call `Date.now` inside them. `ThoughtStore` methods also take `now` with no default; views pass `.now`. Cover changes with tests in `ThoughtRepsTests/`.
- **Reminders: plan purely, schedule in one place.** What to notify and when is `ReminderPlanner` (pure, in `Scheduler/`). Only `NotificationScheduler.reschedule` touches `UNUserNotificationCenter`; it is serialized and removes stale reminders before adding the planned ones, so no more than 10 are ever pending (7 daily plus follow-ups at +14, +30 and +90 days, then silence). Counts come from `fetchCount` with `ReminderPlanner.countedPredicate`, never by loading thoughts; `plan` takes the count as a closure and stays pure. Local notifications only (no push), no app icon badge, and pinned thoughts never count.
- **Tag links go through `TagLinker`.** It rewrites `#tag` to a `thoughtreps-tag:` link before MarkdownUI renders, using `TagParser`'s rules; don't parse tags separately in the renderer.
- **`ThoughtStore` owns all writes.** Views read via `@Query` but mutate (create, edit, schedule, tags, delete) only through the store.
- **Assume hundreds of thousands of thoughts.** Counts and existence checks are `fetchCount`/`fetchLimit` queries with a `#Predicate`, never `@Query` arrays or relationships filtered in memory (SwiftData can't count through `tags?.isEmpty`; see `ThoughtCounts.untagged`). Load `Thought` objects only to display them, and use `propertiesToFetch` when a few fields are enough. No query per thought (a query per tag is fine; tags are few). Keep predicates in reusable builders (`ThoughtCounts`, including the Timeline's `timeline`/`upcoming`/`nextUp` in `Stores/TimelineQueries.swift`, and `ReminderPlanner.countedPredicate`) and test them against an in-memory container. Anything in `body` that scales with thought count belongs in a query or a value refreshed on save. Known exceptions: the Timeline's "show all" mode and the Archive list (they display every thought; the default Timeline queries only pinned, due and recently viewed thoughts) and the DEBUG-only `IntegrityChecker`.
- **Models stay CloudKit-compatible** so iCloud sync can be switched on later without a migration: every stored property has a default, relationships are optional with inverses declared on one side, no `@Attribute(.unique)` (e.g. tag uniqueness is enforced in `ThoughtStore`), and enums are stored as raw strings.
- **Schema changes need a migration, after launch.** The app container is built from `SchemaV1` + `ThoughtRepsMigrationPlan` (`Models/SchemaVersions.swift`). Until the first App Store/TestFlight release, edit `SchemaV1` in place and regenerate `ThoughtRepsTests/Fixtures/default.store` with `FixtureGenerator` (steps in the README beside it). From launch on, `SchemaV1` is frozen: before ANY model change, snapshot V1 into nested copies, then add `SchemaV2` and a migration stage. Never regenerate or edit a shipped fixture; add a new one. `PersistenceTests.openV1FixtureWithMigrationPlan` guards this.
- **Writers set the change clock for every field group they change.** Content (body, blocks, images, tags) is `updatedAt`; schedule (`nextDueAt`, interval, mode, `learnIntervalDays`) is `scheduleChangedAt`; pin/archive is `stateChangedAt`. `markViewed` bumps the schedule clock only when it actually moves `nextDueAt`. `viewCount`/`lastViewedAt` have no clock (import takes the max). `Tag.updatedAt` is set only by an explicit color choice, so implicit tags stay `.distantPast`. A writer that skips its clock lets a backup import silently undo its change. `ThoughtStore.delete` writes a `Tombstone` in the same save (prep for sync; nothing reads them yet, `deleteAll` clears them, and they aren't exported). Extend `IntegrityChecker` with any new clock or tombstone invariant.
- **Saves can fail and must not be swallowed.** `ThoughtStore.persist()` logs, rolls back, and reports to `SaveErrorCenter` (shown as an alert). Store writers return `Bool` (`@discardableResult`); a failed create returns a detached thought (`modelContext == nil`). The editor closes only on success so drafts survive. Rolling back certain write shapes crashes SwiftData, so new writes on a stored thought must follow the rules in the `persist()` note (`update` saves in steps and may be partly saved on failure; `delete` removes children explicitly). Images follow this: new inline images are saved in their own step before the body edit, and inline images whose `![](img:<uuid>)` token left the body are deleted explicitly. `PendingImageSaves` marks a thought across that step; if the edit and the take-back both fail (or the app dies), the mark stays and `cleanUpPendingImageSaves()` (run at launch from `RootTabView`, and by `update` first) deletes the thought's tokenless inline images.
- **Keep the integrity checker and randomized tests current.** `IntegrityChecker` (`Stores/`) is a pure, read-only invariant check that runs at launch in DEBUG and only logs. When adding or changing a model field, store write, or invariant, extend it and the seeded random-operation tests (with injected save failures) so every operation keeps the store violation-free. It covers images too: data and thumbnails present, every inline image has a token and every token resolves, gallery images match their block's thought with contiguous order, images sit only in galleries or inline, no duplicate ids.
- **The search index is derived; keep it in sync.** SQLite FTS5 in `Search/`, next to the store and excluded from backup, never the source of truth. Any `ThoughtStore` writer that changes body, block content or titles, tag names, or archive state must submit a reindex; index errors are logged, never shown as save errors. `SearchReconciler` repairs drift at launch (off the main thread, via an `updatedAt` + archive-flag fingerprint) and rebuilds a missing or damaged file. Known gaps: after a mid-session index failure search is incomplete until next launch, and a write that leaves `updatedAt` unchanged can leave stale text until the next edit. Extend `SearchIndexChecker` and the randomized tests when changing any of this.
- **The share extension never touches SwiftData.** `ThoughtRepsShare` only writes `InboxItem` files into the App Group inbox via `Shared/`; the app imports them through `InboxImporter` -> `ThoughtStore.create`. The store stays in the app container: moving it to the App Group would need a migration plan, so don't do it casually. Keep the extension free of MarkdownUI and SwiftData (extension memory limit).
- **The app's only network calls are to our API** (`transfer.thoughtreps.com/api/v1`) **and presigned S3**. Feedback and creating or revoking an export link go through `AppAttestClient`; the public, unsigned export-link `status`/`claim`/`done` calls (`ExportLinkImportService`, for importing a link) and the presigned S3 `PUT` (upload) and `GET` (download) of the encrypted export need no App Attest. Feedback never includes thought content; an export link upload does carry it, but only as a file encrypted on device (AES-GCM) whose key never leaves the device except in the link's URL fragment, and importing decrypts on device with that fragment. The share extension stays network-free. App Attest is unavailable in the simulator, so sending feedback or creating an export link needs a real device; Universal Links (`applinks:transfer.thoughtreps.com`) can't be tested there either.
- **Privacy manifests and the privacy policy change together.** Changing network calls, data the app sends or stores off-device, server-side records, or adding a required-reason API means updating both `PrivacyInfo.xcprivacy` files (`ThoughtReps/Resources/`, `ThoughtRepsShare/`) and the privacy policy (`site-landing/src/content/privacy.ts`) in the same change. Release checks (App Store privacy answers, export compliance) are in DEVELOPMENT.md, "Releasing to the App Store".
- **Generated plists and entitlements come from `project.yml`** (`info:`/`entitlements:`, gitignored output); never hand-edit them.
- **Themes go through the Ink tokens.** Colors, fonts and card shapes come from `InkStyle.swift`, which reads `ThemeManager` (`AppTheme.swift`); don't hard-code them in views. The Ink theme must stay identical to the asset catalog (`InkStyleTests`). Always-dark themes pin the windows' `overrideUserInterfaceStyle`, since `preferredColorScheme(nil)` can't reliably undo a forced scheme. Settings and the editor keep the standard iOS look. The choice is in UserDefaults (no schema change). Premium themes are only an idea (TODO.md).
- **The rating prompt state lives in UserDefaults, not SwiftData** (`RatingPrompt`; no schema change). A due open is decided by the pure `Scheduler.countsAsDueOpen` inside `markViewed`, and a Learn rating (`review`) counts as a due open too; at 10 the prompt is asked once ever, from the main timeline. Tests that call `markViewed` or `review` must inject a throwaway suite (`RatingPrompt.throwaway()`), never the standard defaults.
- **The reminder prompt is UserDefaults too** (`ReminderPrompt`, key `reminderPromptAsked`; no schema change). Offered once ever, after the editor closes on the first thought created there. Tests use throwaway suites.
- **Layout follows `horizontalSizeClass`.** Regular width is the three-column `SplitRootView`, compact is the iPhone tab view. `ThoughtSelection` (environment object) exists only in the split layout; list rows are `ThoughtLink` (a selection button there, a `NavigationLink` otherwise), and anything that leaves a thought (snooze, archive, delete) goes through `leave()`. Never auto-select a thought: opening one is a view and requeues it. Editor sheets are presented from the root, so they survive a window resize.
- **One scene only.** Multiple windows are disabled (`UIApplicationSupportsMultipleScenes` off) because `AppNavigation`, `EditorShortcuts` and `BackupModel` are singletons; per-scene state comes first. Keyboard shortcuts (`AppCommands`, the editor's ⌘↩/Esc) are guarded by `ModalPresence` so they pause under a sheet or dialog. Dropped images go through `ImageIntake`, the same processing as the picker; non-image links are ignored, never fetched.
- **If the store can't open, show the error screen** ("Couldn't open your thoughts"); never fall back to creating an empty store.
- **Every documentation pass checks the help center.** `site-landing/src/content/help.ts` is user-facing product documentation, prerendered at thoughtreps.com/help, and must match what the shipped app does. A change that adds, removes or alters a user-facing feature, UI label, limit, setting or workflow updates the matching article; a brand-new feature gets a new article. Write only what's in the shipped app (not unshipped Study mode). Keep `related` slugs pointing at existing articles, and link new articles to and from related ones. Keep the casual, plain voice (a Flesch-Kincaid test caps each article), and refer to icons with `{icon:name}` tokens rather than naming them. When a UI label or screen changes, update or add the matching `example` mockup in `HelpExamples.tsx` (real labels and states from the Swift app). New icon glyphs come only from Lucide, and `site-landing/public/third-party-licenses.txt` (and `transfer-web/public/`'s) stays current. Tests enforce title (<=70) and description (<=160) lengths; the sitemap, robots.txt, per-page SEO and JSON-LD, and the Open Graph tags and link-preview cards (`og/*.png`, rendered by `src/og-image.tsx` at prerender) generate from `help.ts`, so don't hand-edit them. Each article's "Updated" date is its newest line in `git blame` at prerender (`content/helpDates.ts`), so deploy from committed changes.
- **The blog (`site-landing/src/content/blog.ts`, /blog) is SEO content for people new to the app.** Essays first: mention the app lightly, and only for what it ships. Same section format, inline syntax and generated SEO as help (`BlogPosting` JSON-LD). Check historical or factual claims before publishing. Tests cap reading level at grade 7.

## Product decisions

- **Opening a thought requeues it, unless it's in Learn mode.** `ThoughtDetailView` calls `ThoughtStore.markViewed` on appear for fixed-interval thoughts. Learn mode (`IntervalMode.learn`, per thought, off by default) is the shipped part of Study mode: opening doesn't requeue, and a due Learn thought moves only via **Again** / **Got it** (`ThoughtStore.review`; `setLearnMode` toggles). The growth math is pure, in `Scheduler.afterReview`: Got it multiplies the last wait (`Thought.learnIntervalDays`, starts at the thought's interval) by 1.7, at least +1 day, capped at 365; Again is tomorrow and resets the wait. Learn state is in the backup (`learnIntervalDays`). Don't change requeue-on-open for fixed thoughts without asking; the rest of Study mode (a deck, spec) is unbuilt.
- **v1 blocks are markdown (optionally blurred) and image galleries** (`BlockKind.markdown` with `Block.isBlurred`, `BlockKind.gallery`). The thought `body` is the first markdown block and stays on `Thought`. Old stored or exported kind "blurred" means blurred markdown (`migrateLegacyBlurredBlocks` at launch; import maps it).
- **Images live in SwiftData, not as files** (differs from the spec). `ImageAsset` data and thumbnails are `.externalStorage`, so large bytes sit in `.default_SUPPORT/_EXTERNAL_DATA` beside `default.store`; the backup export reads image bytes through SwiftData, but any file-level backup must include that folder. `ImageProcessor` downsizes to 2048 px HEIC (JPEG fallback) and strips metadata. The renderer resolves `img:` URLs only from the thought's own images, never the network.
- **The `.thoughtreps` backup format is permanent.** A zip (`ThoughtReps/Services/Backup/`) whose first entry is a stored `mimetype` (`application/vnd.thoughtreps.export+zip`), then `manifest.json` (`formatVersion`, SHA-256 per entry), `tags.jsonl`, `thoughts.jsonl`, `images/<uuid>`. Bump `formatVersion` on any record change; once shipped, old versions must stay importable. Exception: record changes made before any build has shipped don't bump it; the rule applies from the first TestFlight/App Store release. Import validates contents, not extension, and goes only through `ThoughtStore.importThoughts`: merge by thought id, group by group: content by `updatedAt`, schedule by `scheduleChangedAt`, pinned/archived by `stateChangedAt`, view counters by max, tag colors by `Tag.updatedAt`; each clock follows the winning side. Tags are derived from the body. Importing from an export link downloads to a temp file and hands it to `BackupModel.beginImport`, so it takes the same path; opening a link (Universal Link, `applinks:transfer.thoughtreps.com`) only shows status and never claims, since claiming burns the one-time link. The export link uploads this same file, encrypted on device (`TRB1` + nonce + ciphertext + tag, AES-256-GCM); the key stays in the link's `#` fragment and, until expiry, in the Keychain so Settings can re-offer or revoke it. Known limit: ZIPFoundation rewrites the central directory per entry, so export time is quadratic in image count (~1 s at 4k images, ~100 s at 40k).
- **No legacy data import for now.** Export/import is only for the app's own format. Importing the original Thought Reps data is still an open question in the spec; don't build it until that's answered.
