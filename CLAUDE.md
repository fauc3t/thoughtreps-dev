# Thought Reps

Local-first iPhone and iPad app: write a Markdown thought, and it resurfaces on the timeline after an interval (7 days by default). Specs, plans and mockups live in `designs/` (new specs go there too); `landing/` is static landing-page prototypes (not shipped; `site-landing/` is the real landing site, a port of `landing/7-ink.html`, plus the prerendered help center at /help, the blog at /blog, and the privacy policy at /privacy and the support page at /support). `infra/` is the CDK app (landing hosting, DNS, email at hello@thoughtreps.com), `infra/mail-web/` the inbox UI, and `transfer-web/` the one-time export download page; see `infra/CLAUDE.md`. `content-pipeline/` holds unpublished blog and free-tool (printables) ideas and drafts (workflow in its `README.md`). `app-store-assets/` holds App Store product page and search creative, one folder per slot (regeneration steps in each slot's `README.md`). What's deployed in AWS is recorded in `INTEGRATIONS.md`. The sync server lives in the separate `~/dev/thoughtreps-aws` repo. Setup and commands are in README.md and DEVELOPMENT.md.

## Stack

Swift, SwiftUI, SwiftData, iOS 18+, Swift Testing. Two third-party dependencies, both pinned exact: MarkdownUI (chosen over Textual as the stable option, though it's in maintenance mode) and ZIPFoundation (the backup zip). Add packages via `project.yml` `packages:`; the SwiftPM lockfile `ThoughtReps.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` is tracked, so commit it when versions change. Paid Apple Developer account. The web side is TypeScript in a pnpm workspace (`infra`, `infra/mail-web`, `site-landing`, `transfer-web`; Node 24+); tests are `pnpm test`, `pnpm typecheck`, `pnpm lint` at the root.

## Workflow

- Web/infra deploys are manual `cdk deploy` with `--profile thoughtreps-prod-legacy` (no CI), into an AWS account shared with strands prod. Read `infra/CLAUDE.md` first, and update `INTEGRATIONS.md` when a deploy changes a stack's status, outputs or ids (content-only deploys need no entry).

- `project.yml` is the source of truth. `ThoughtReps.xcodeproj` is generated and gitignored: edit `project.yml`, run `xcodegen`, never hand-edit the project. Re-run after adding or removing files.
- Signing lives in `Config/Local.xcconfig` (gitignored, copy from the `.example`).
- Test: `xcodegen && xcodebuild test -scheme ThoughtReps -destination 'platform=iOS Simulator,name=<simulator>'`, with a name from `xcrun simctl list devices available`.

## Rules

Detail lives in `designs/`, in each doc's "As built" section: **Design Spec** (`Thought Reps for iPhone — Design Spec.md`, "As built: app rules"), **Sync Spec** (`Thought Reps — Sync Spec.md`, "As built: client rules"), **Harness Spec** (`Thought Reps — Device Sync Harness Spec.md`, "As built: cleanup and probes"). Read the matching one before changing that area.

- **Scheduling is pure.** Resurfacing logic lives in `ThoughtReps/Scheduler/` as pure functions that take `now` as a parameter; never call `Date.now` inside them. `ThoughtStore` methods also take `now` with no default; views pass `.now`. Cover changes with tests in `ThoughtRepsTests/`.
- **Reminders: plan purely, schedule in one place.** `ReminderPlanner` (pure) decides what to notify; only `NotificationScheduler.reschedule` touches `UNUserNotificationCenter`. Max 10 pending, local only (no push), no badge, pinned thoughts never count. (Design Spec, "Reminders".)
- **Tag links go through `TagLinker`** (rewrites `#tag` to a `thoughtreps-tag:` link before MarkdownUI renders, using `TagParser`'s rules); don't parse tags separately in the renderer.
- **`ThoughtStore` owns all writes.** Views read via `@Query` but mutate only through the store.
- **Assume hundreds of thousands of thoughts.** Counts and existence checks are `fetchCount`/`fetchLimit` queries with a `#Predicate`, never `@Query` arrays or in-memory filtering; load `Thought` objects only to display them; no query per thought. Keep predicates in reusable builders (`ThoughtCounts`, `Stores/TimelineQueries.swift`) tested against an in-memory container. Anything in `body` that scales with thought count belongs in a query or a value refreshed on save. (Design Spec, "Scale", for builders and exceptions.)
- **Models stay CloudKit-compatible:** every stored property has a default, relationships are optional with inverses declared on one side, no `@Attribute(.unique)` (tag uniqueness is enforced in `ThoughtStore`), enums stored as raw strings.
- **Schema changes need a migration, after launch.** The container is `SchemaV1` + `ThoughtRepsMigrationPlan` (`Models/SchemaVersions.swift`). Until the first external TestFlight or App Store release (internal TestFlight is still pre-launch), edit `SchemaV1` in place and regenerate `ThoughtRepsTests/Fixtures/default.store` with `FixtureGenerator` (README beside it); testers then delete and reinstall, or the store fails to open. After that `SchemaV1` is frozen: before ANY model change snapshot V1 into nested copies, add `SchemaV2` and a migration stage, and never edit a shipped fixture (add a new one). `PersistenceTests.openV1FixtureWithMigrationPlan` guards this.
- **Writers set the change clock for every field group they change,** via the store's skew-safe `stamp`: content (body, blocks, images, tags) is `updatedAt`; schedule is `scheduleChangedAt`; pin/archive and `conflictOfID` are `stateChangedAt`. A writer that skips its clock lets a backup import silently undo its change. `ThoughtStore.delete` writes a `Tombstone` in the same save. Extend `IntegrityChecker` with any new clock or tombstone invariant. (Design Spec, "Change clocks".)
- **Saves can fail and must not be swallowed.** `ThoughtStore.persist()` logs, rolls back, and reports to `SaveErrorCenter`; writers return `Bool`; the editor closes only on success. Rolling back some write shapes crashes SwiftData, so follow the `persist()` note for new writes on a stored thought. Inline images save in their own step before the body edit (`PendingImageSaves`). (Design Spec, "Save failures".)
- **The sync outbox is derived state; keep it fed.** `sync.sqlite` (`Sync/`) is never the source of truth. Every `ThoughtStore` writer that changes a synced field or clock enqueues via `syncState.enqueue`, alongside the reindex (extend the randomized tests' outbox drain check). Editor saves go through `ThoughtStore.saveEdit` (3-way merge); remote changes apply only via `ThoughtStore.applyRemote` and must not enqueue echoes; no base with differing content makes a conflict copy, never a guess. Wire formats are frozen (`SyncWireV1`, `SyncHTTPWireV1`; the latter's golden fixtures in `ThoughtRepsTests/Fixtures/SyncWireV1/` mirror `thoughtreps-aws` byte for byte, so change both), as are the recovery code and `nameSealed` formats; an unknown `TR*` magic or key generation parks as update-required, never an error. Never persist or log the session token or vault key. Leaving sync and erase are local only (no "Erase on all devices"). Sync is DEBUG-only for now. (Sync Spec, "As built: client rules", for auth, pairing, blobs, leave/delete, resume, GC.)
- **Test vaults get cleaned up** by the device harness ledger and reset (UI tests launch with `syncSaveKeyToICloudKeychain` off). Harness Spec.
- **Keep the integrity checker and randomized tests current.** `IntegrityChecker` (`Stores/`) is a pure, read-only invariant check that runs at launch in DEBUG and only logs. When adding or changing a model field, store write, or invariant (images included), extend it and the seeded random-operation tests (with injected save failures).
- **The search index is derived; keep it in sync.** SQLite FTS5 in `Search/`, excluded from backup, never the source of truth. Any `ThoughtStore` writer that changes body, block content or titles, tag names, or archive state must submit a reindex; index errors are logged, never shown as save errors. Extend `SearchIndexChecker` and the randomized tests with any change. (Design Spec, "Search index", for known gaps.)
- **The share extension never touches SwiftData.** `ThoughtRepsShare` only writes `InboxItem` files (plus one copied attachment) into the App Group inbox via `Shared/`; the app imports them through `InboxImporter` -> `ThoughtStore.create`. The store stays in the app container (moving it needs a migration plan). Keep the extension free of MarkdownUI and SwiftData (memory limit) and network-free.
- **The app's only network calls are to our API** (`transfer.thoughtreps.com/api/v1`) **and presigned S3**, plus DEBUG-only sync to a dev or local server. Feedback and export links go through `AppAttestClient`; feedback never includes thought content, and an export upload carries it only encrypted on device. App Attest and Universal Links can't be tested in the simulator. (Design Spec, "Network"; Sync Spec, "Network scope".)
- **Privacy manifests and the privacy policy change together.** Changing network calls, data sent or stored off-device, server-side records, or adding a required-reason API means updating both `PrivacyInfo.xcprivacy` files (`ThoughtReps/Resources/`, `ThoughtRepsShare/`) and `site-landing/src/content/privacy.ts` in the same change (both change again when sync ships). Release checks: DEVELOPMENT.md, "Releasing to the App Store".
- **Generated plists and entitlements come from `project.yml`** (`info:`/`entitlements:`, gitignored output); never hand-edit them.
- **Themes go through the Ink tokens** in `InkStyle.swift`; don't hard-code colors, fonts or card shapes in views. Ink must stay identical to the asset catalog (`InkStyleTests`). Settings and the editor keep the standard iOS look.
- **Prompt state (`RatingPrompt`, `ReminderPrompt`) lives in UserDefaults, not SwiftData.** Tests that call `markViewed` or `review` must inject a throwaway suite (`RatingPrompt.throwaway()`), never the standard defaults.
- **Layout follows `horizontalSizeClass`:** regular width is the three-column `SplitRootView`, compact the tab view. `ThoughtSelection` exists only in the split layout; list rows are `ThoughtLink`; anything that leaves a thought goes through `leave()`. Never auto-select a thought (opening requeues it); the one exception is a fold/unfold (`LayoutCarry` + `ViewHandoff`, so nothing records a second view). Editor sheets are presented from the root. (Design Spec, "Layout".)
- **One scene only** (multiple windows are disabled; `AppNavigation`, `EditorShortcuts` and `BackupModel` are singletons). Shortcuts are guarded by `ModalPresence`. Dropped images go through `ImageIntake`, other files through `FileIntake`; non-file links are never fetched.
- **New-thought requests go through `AppNavigation.requestNewThought`**; App Intents only call it and never touch SwiftData.
- **Conflict copies (`conflictOfID` set) are resolved, not browsed.** They stay out of the default timeline, `upcoming`, the main show-all and `ReminderPlanner.countedPredicate`; the "Needs a look" row opens `ConflictResolveSheet`, never `ThoughtDetailView`, so a copy is never requeued. This ships in release builds, unlike the rest of sync.
- **If the store can't open, show the error screen** ("Couldn't open your thoughts"); never fall back to creating an empty store.
- **Every documentation pass checks the help center.** `site-landing/src/content/help.ts` (thoughtreps.com/help) is user-facing documentation and must match the shipped app. A change that adds, removes or alters a user-facing feature, label, limit, setting or workflow updates the matching article and its `HelpExamples.tsx` mockup; a new feature gets a new article. Write only what's shipped (not unshipped Study mode). Sitemap, SEO and Open Graph output are generated; don't hand-edit. The blog (`blog.ts`) is SEO essays, not product docs. Full rules: DEVELOPMENT.md, "Help center and blog content".

## Product decisions

- **Opening a thought requeues it, unless it's in Learn mode.** `ThoughtDetailView` calls `ThoughtStore.markViewed` on appear for fixed-interval thoughts. Learn mode (`IntervalMode.learn`, per thought, off by default) is the shipped part of Study mode: opening doesn't requeue, and a due thought moves only via **Again** / **Got it** (`ThoughtStore.review`; pure `Scheduler.afterReview`, Design Spec "Learn mode"). A visit from a link card (`ThoughtStore.recordVisit`) bumps only `viewCount`/`lastViewedAt`. Don't change requeue-on-open for fixed thoughts without asking; the rest of Study mode is unbuilt.
- **v1 blocks are markdown (optionally blurred), image galleries, thought links and files.** A link block holds only `Block.linkedThoughtID`, a plain id with no relationship (it may dangle; at most one link per target, never to itself; no search text; adding or removing one is a content change). Spec: `designs/Thought Reps — Linked Thoughts Spec.md`. File blocks hold one `FileAsset` capped at 5 MB (Design Spec, "Blocks, images and backup"). The thought `body` is the first markdown block and stays on `Thought`.
- **Images and attached files live in SwiftData, not on disk** (differs from the spec): `.externalStorage` bytes sit in `.default_SUPPORT/_EXTERNAL_DATA` beside `default.store`, which any file-level backup must include. The renderer resolves `img:` URLs only from the thought's own images, never the network.
- **The `.thoughtreps` backup format is permanent.** Bump `formatVersion` on any record change once shipped (before the first external release, don't); old versions must stay importable. Import goes only through `ThoughtStore.importThoughts`. Opening an export link only shows status and never claims, since claiming burns the one-time link. (Design Spec, "Backup file layout", "Blocks, images and backup".)
- **No legacy data import for now.** Export/import is only for the app's own format; importing the original Thought Reps data is an open question in the spec, so don't build it.
